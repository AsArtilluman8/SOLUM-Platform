# SOLUM Marketplace and Monetization Concepts

Status: strategic concept document.

This document records possible future monetization and marketplace directions. It is not a final business model, legal agreement, or revenue promise.

SOLUM should remain open-source while still allowing creators, package authors, asset authors, and platform maintainers to benefit from the ecosystem if it grows.

## Principles

- The core engine should remain free and open-source.
- Public project claims must not promise revenue-share until the legal and technical foundation exists.
- Assets and packages need clear licenses.
- Users should understand what their project depends on.
- Creators should receive attribution and, where applicable in future systems, compensation.

## Possible Monetization Paths

Potential paths:

- donations;
- sponsorships;
- GitHub Sponsors or similar platforms;
- verified creator packs;
- paid optional asset/mechanic packs;
- revenue-share package ecosystem;
- professional support;
- future independent distribution platform.

No single option is locked in yet.

## Revenue-Share Concept

A future revenue-share model could allow:

- free engine usage;
- free or paid packages;
- optional creator revenue when a shipped game earns revenue;
- platform share for hosting, tooling, verification, and ecosystem work.

This requires significant groundwork.

## Required Technical Foundation Before Revenue Share

A revenue-share system requires:

- package manifests;
- license tracking;
- attribution tracking;
- creator identity/verification;
- package dependency reports;
- project export reports;
- version tracking;
- conflict resolution;
- clear terms of use;
- legal review;
- transparent accounting.

Without this, revenue-share would be confusing and unsafe.

## Package Marketplace Concept

Future marketplace/package hub items may include:

- assets;
- materials;
- VFX;
- mechanic packages;
- animation packs;
- UI kits;
- audio packs;
- scene templates;
- agent skills;
- tutorials/examples.

Potential metadata:

- rating;
- reviews;
- author;
- version;
- license;
- screenshots/previews;
- test scene;
- dependencies;
- supported SOLUM version;
- performance tier;
- mobile cost warning.

## Asset Cloud Concept

SOLUM should avoid shipping large assets inside the base APK whenever possible.

Future asset distribution can use:

- official starter packs;
- community packs;
- cloud-hosted packs;
- local cache;
- versioned downloads;
- mirrors for open/public assets.

Only license-compatible assets should be included in public official packages.

## Independent Store / Launcher Concept

A future independent app/game distribution platform could give more control over:

- publishing;
- updates;
- package dependencies;
- revenue-share;
- creator attribution;
- community discovery.

This is a long-term concept, not a near-term foundation goal. The immediate priority is engine/editor foundation, package metadata, and open-source community trust.

## Near-Term Practical Steps

Before monetization decisions:

1. define package manifest schema;
2. define asset/package attribution reports;
3. define licenses accepted by official packages;
4. add local Package Hub foundation;
5. add community contribution rules;
6. create clear documentation for creators.
